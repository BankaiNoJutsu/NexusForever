# Spell Effect Evidence Matrix

This matrix tracks effect-family decoding evidence. It is intentionally family-first: each row should accumulate representative spell IDs, sniff observations, client-decompile hints, local runtime output, known field mappings, unknowns, and validation status.

## Field Legend

- Raw row: `Spell4EffectsEntry`
- Core identity: `Id`, `SpellId`, `OrderIndex`, `EffectType`, `TargetFlags`, `DamageType`
- Timing: `DelayTime`, `TickTime`, `DurationTime`
- Opaque fields: `DataBits00` through `DataBits09`
- Parameter vectors: `ParameterType[0..3]`, `ParameterValue[0..3]`
- Apply/persistence hooks: `PrerequisiteIdCasterApply`, `PrerequisiteIdTargetApply`, `PrerequisiteIdCasterPersistence`, `PrerequisiteIdTargetPersistence`, `PrerequisiteIdTargetSuspend`

## Structural Findings

- `Spell4Base` is base identity and target shape.
- `Spell4` is concrete tier, cast/channel/cooldown/cost/charge/runtime-hook data.
- `Spell4Effects` is ordered behavior data.
- `Spell4Telegraph` and `TelegraphDamage` are target acquisition geometry/timing, not just visuals.
- `SpellEffectType` gives per-family metadata for the ten opaque `DataBits` slots.
- Jabbithole data maps content to spells; the optional world database maps placed creatures to content context.
- Effect-level `TargetFlags` distribution confirms the server enum shape: caster (`0x01`), explicit target (`0x02`), telegraph targets (`0x04`), and rare unknown bit `0x08`.
- Concrete `Spell4` min/max/vertical range and `Spell4TargetAngle` facing cones now validate explicit primary targets before execution. `Spell4ValidTargets` bit `0x08` is enforced as the dead-target/corpse allowance for explicit targets and telegraph candidates. SQL witnesses now also strongly identify bit `0x02` as an interactable/world-object category through rows like `Activating`, `Harvesting`, `Repairing Machinery`, and `Placing wanted poster`, while composite mask `0x0A` appears on corpse-interaction rows such as `Blood Extractor - Discovery - Targets Corpse`. The spell core now resolves explicit primary targets through `IWorldEntity`, enforces `0x02` for non-unit interactables, and carries those targets through selection and spell-start anchoring. Non-unit effect routing is still intentionally narrow, but the proven activation-object slice now runs there: `Activate`, `SetBusy`, `DespawnUnit`, diagnostics-only `RavelSignal`, and `Fluff`. `primary-target-validation` traces preserve the target mechanics row, target angle, and valid-target bitmask for further decoding.
- `Spell4TargetMechanics.targetType` rows named by client test spells now drive conservative runtime structure: type `1` single target, type `3` target AOE, type `4` position AOE, and type `5` chain target. Player casts forward the selected target for target-dependent types, and telegraph/AOE constraint origins follow target or supplied position anchors where available.
- `Spell4AoeTargetConstraints` now filters telegraph-selected targets by min/max range and angle around the resolved AOE origin, caps by `TargetCount`, and supports all observed selection modes `1..5`: closest, furthest, random, lowest absolute health, and most missing health. SQL naming strongly witnesses mode `3` as random-targeting through rows such as `31300`, `51744`, `62710`, `63209`, `74323`, and `74575`; non-dead valid-target masks remain evidence-only.
- `Proc.DataBits01` resolves to a trigger `Spell4.ID` for 3,423 of 3,498 rows. `DataBits02` is a float-bitcast chance with dominant values `1.0`, `0.5`, `0.35`, `0.3`, `0.25`, `0.2`, `0.15`, `0.1`, and `0.05`. `DataBits00` is the trigger-event id, with strongly named clusters such as event `1` on-kill, `6` enter-combat, `10` action-cast-any, `12` deal damage/on hit, `16` get-damaged-any, `17/18/19` get-damaged Melee/Ranged/Magic variants, and `20` heal-other. Local Spell4 name clusters now safely map `17/18/19` onto `Spell4Base.School` buckets `Melee`/`Ranged`/`Spell`, while `Unarmed` remains on generic event `16` because no distinct unarmed proc family is evidenced. `DataBits03` is target/routing data; routes `1/2/4/9/12` are now safe to enforce, while other tails remain diagnostic-only.
