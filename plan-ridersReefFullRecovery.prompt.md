## Plan: Riders Reef Full Recovery

Retail-complete Rider's Reef should be treated as a world-import plus runtime parity problem. The official tutorial world SQL already contains the missing course objects, including multiple arrows, rings, boosters, pressure plates, finish-line objects, hazards, and projectors, so the first implementation target is to make imported NPE entities and their behavior authoritative, then close remaining interaction/selectability and quest-handoff gaps with data-backed runtime fixes.

**Steps**
1. Phase 1: Establish the authoritative Rider's Reef entity inventory. Extract every Rider's Reef relevant entity from the sibling official tutorial world SQL, including creature id, entity type, coordinates, scriptName, QuestChecklistIdx, Mode, ActivePropId, and part/section grouping. Compare that inventory against the current hardcoded tutorial world-location and cluster assumptions in Player and TutorialMapScript. Produce a durable artifact under artifacts/verify or extend Tools/QuestTableInspector to print a Rider's Reef crosswalk. This blocks all later phases.
2. Phase 1: In parallel with step 1, capture the current runtime truth on this branch. Verify which imported world 3460 entities actually spawn, which entity scripts initialise, which Rider's Reef projectors route through direct activate versus activate-cast, and which interactions fail due to visibility wrapper, range, busy state, or activate-spell prerequisite checks. Use current worldserver logs plus fresh traces around ClientEntityInteractionHandler, ClientActivateUnitHandler, ClientActivateUnitCastHandler, and ActivationInteractionGuards. Parallel with step 1.
3. Phase 2: Replace the current small tutorial cluster model with imported-world parity. Audit Player's Rider's Reef visibility sync and hardcoded creature-id list against the official tutorial entity set. Decide object-by-object which imported entities should be always spawned, which need per-player phasing, and which should stop being hardcoded special cases. Expand or restructure visibility logic so it can handle the official set, including 72051 arrows, 70939 rings, 73461 boosters, 73416 holorings, 73707 start arrows, 74767-74769 pressure plates, 73595 finish-line objects, 73736 combat hologram, and part-2 hazards or mines where appropriate. Depends on 1-2.
4. Phase 2: Restore the missing entity-script behavior surface. The official tutorial world SQL attaches script names such as DirectionArrowEntityScript, DirectionArrowPt2EntityScript, ObjectiveRingEntityScript, and ObjectiveRingPt2EntityScript, but this branch currently exposes entity_script loading without matching implementations for those names. Decide whether to implement local replacements, port isolated equivalents from a compare branch if they exist, or reproduce only the proven behavior from runtime or decomp evidence. Treat TutorialCombatProjectorEntityScript as the working reference for how imported tutorial entity scripts should behave. Depends on 1-2 and can run in parallel with step 3 once the object inventory is stable.
5. Phase 3: Fix projector selectability and activation semantics across all Rider's Reef projector-like entities. Add narrow diagnostics for entity visibility lookup failure, range bounds, busy rejection, and activate-spell resolution. Reconcile the direct-activate and activate-cast handlers so projector behavior is consistent regardless of which client opcode fires. Validate imported projector entries against their creature table prerequisites and any script-bound behavior. Depends on 2 and is partly parallel with step 4.
6. Phase 3: Keep the quest progression repair conservative but update it to the full world parity pass. Preserve the proven EnterArea geometry, optional-objective ordering, login replay, hoverboard recovery, and receiverless starter handoff work already on the branch. Narrow the remaining chain work to the actual unresolved seams: post-hoverboard handoff and combat-projector flow after imported world content is authoritative. Do not reopen QuestDirection or objective-world-location work unless the Rider's Reef crosswalk shows a concrete mismatch, because tutorial guidance packets are already emitted and these tutorial quests are still negative controls for direct indicator routing. Depends on 1-2 and should be validated after step 3 so world-content parity does not fight the quest fix.
7. Phase 4: Verify that world-import infrastructure is not silently dropping Rider's Reef content. Confirm the official tutorial world SQL is applied from the sibling world-database checkout, entity_script rows survive import, entity.mode and questChecklistIdx values persist, and the current compatibility filters are not omitting Rider's Reef rows. If import fidelity is incomplete, fix the world schema or importer before adding more script-side hacks. Depends on 1 and can run in parallel with steps 3-6.
8. Phase 4: Use compare or decomp only where the behavior is still ambiguous after the data crosswalk. Priority reverse-engineering targets are entity mode semantics, the missing objective ring or direction arrow script behaviors, and any client expectations around projector interaction or selectability that are not explained by current server logs. Use the compare branch as a parts bin, not a merge target. Depends on 1-7 findings.
9. Phase 5: Validate end-to-end retail-complete Rider's Reef on both factions. Verify all imported course elements relevant to the tutorial appear or phase correctly, 73419 and 73735 remain selectable and functional, hoverboard course progression works in-session and after relog, the combat transition works on both Exile and Dominion, and world 3460 no longer relies on a tiny hardcoded cluster to approximate the tutorial. Depends on 3-8.

**Decisions**
- First milestone is retail-complete Rider's Reef world parity, not just a minimally playable tutorial.
- Use a mixed approach: do minimal runtime instrumentation first, then resolve missing behavior with data-backed parity work.
- Treat the official tutorial world SQL as authoritative for Rider's Reef course content; the current small creature-id cluster is an approximation and should no longer be the main source of truth.
- Keep existing proven tutorial fixes for WorldLocation2 trigger geometry, optional-objective ordering, login recovery, and starter-chain repair unless the official world or content audit proves a regression.
- De-prioritize broad QuestDirection and ServerQuestObjectiveWorldLocation work for Rider's Reef specifically; current tutorial quests already serve as negative-control guidance witnesses and live logs show the guidance packet being sent.
- Excluded scope: bulk-merge of another branch, broad spell-system rewrites, and unrelated zone restoration.
