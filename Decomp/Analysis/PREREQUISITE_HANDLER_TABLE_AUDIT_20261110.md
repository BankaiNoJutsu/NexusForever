# Prerequisite native handler audit (2026-11-10)

Evidence tier: **native body read** for the evaluator switch and the 19 handler bodies named in section 3; **generated by parsing decompiler output** for everything else (`scripts/prerequisite_evaluator_case_map.py`);
raw table counts from `wildstar_client`. No server behaviour was changed by this audit. No retail parity claim.

## 1. Finding
`PrerequisiteManager_EvaluateTypeSlot` (`1404a2100`) is the client prerequisite evaluator: a switch on the type word with 271 cases. 208 cases call a method of the
manager through its vtable (`140b67740 + offset`), 51 are inline or call a helper directly, 12 join another case, and
40 vtable cases land on the shared stub `140001ba0`.

An older reading treated the pointer run as a table indexed by type from base `140b67870` ("handler table[N]"). Nothing references `140b67870` and it is not a table base. Every label and source comment
written from that reading attributes a function to the wrong type: of the 51 types whose server source cites a "handler table" address, **50 are contradicted**
(49 of them have a server check).

## 3. Labels corrected
Eighteen labels whose names described the wrong check were re-read and renamed (old name kept in each comment after "SUPERSEDES"), and `14049c620` (type 4) was added:
`14049e820`, `14049e850`, `14049f3d0`, `14049f460`, `14049f5b0`, `14049f690`, `14049fb50`, `14049fbe0`, `14049fc70`, `14049fd80`, `1404a0540`, `1404a0590`, `1404a0b70`, `14049d3f0`, `14049efc0`, `14049e540`,
`14049e610`, `14049ecc0`. `14049fd50` was renamed in the previous pass. The new names end in `_LiveCaseXX` (the evaluator case in hex).

**Not corrected:** other handler labels still carry names from the old reading. The generated map shows, for example, type 143 (Difficulty) reaching `Prerequisite_CheckMovementMode`, type 26 (InSubZone) reaching
`Prerequisite_CheckWaypoint`, type 109 reaching `Prerequisite_CheckItemQuantity` and type 245 reaching `Prerequisite_CheckItemTradeSkill`. Those bodies were not re-read. The stub `140001ba0` is labelled
`ClientCraftingAbandon_WritePayload`, which is one of its many shared uses.

## 4. What this means for the server
A contradicted citation does not by itself mean the check is wrong: several check classes were rewritten on 2026-11-07 from the right body (type 38 is one) and only the enum comment still cites the old address.
The audit file therefore records, per handled type, whether the check class names its native evidence (handler entry, vtable offset or evaluator case):

* 194 types have a server check; 83 check classes name the native code the map points at; **111 do not**.
* Spell data depends on prerequisites through 26,855 references from `Spell4` and `Spell4Effects` prerequisite columns (cast, persistence, runner, AoE and effect apply/persist/suspend). 8,718
  of those land on checks that name their native code, **17,035 on checks that do not**, and 1,102 on unhandled types.

"Does not name its native code" is a text heuristic and a review queue, not a verdict. Inline cases have no entry or offset to cite, so a correct check for an inline type can still be listed.
