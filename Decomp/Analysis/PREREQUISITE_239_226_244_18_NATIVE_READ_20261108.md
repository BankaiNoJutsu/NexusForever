# Prerequisite types 239, 226, 244, 18: writers and meaning

Dispatcher `PrerequisiteManager_EvaluateTypeSlot` `1404a2100`; vtable base `140b67740`. Vtable slots read directly: +0xb8 `14049ca10` (case 0xef, type 239), +0xc0 `14049ca70` (case 0xf4, type 244), +0x390 `14049ef00` (case 0x12, type 18), +0x670 `1404a1620` (case 0xe2, type 226). ## Q1. Type 239 ActionBar: confirmed, it is the per-action-set (spec) unlock flag. Confidence: read directly.
- `14049ca10(this, subject, comparison, Value)`: subject type (`+0x80`) must be 0x14 or 0x17, else false. `flag = DAT_140c65898[+0x1448 + Value*4] & 1` for Value 0..3 (else false). Equal returns flag, NotEqual returns !flag, other comparisons false.
- Only runtime writer: `LuaEvent_ActionSetError_Raise` `1403b97a0`, the apply of `ServerActionSet` opcode **0x019D**, call site `1403ef021` (case start `1403ef01b`). It stores `dword[+0x1448 + setIndex*4] = packet.Unlocked` (also rebuilds the 0x30 shortcut slots, `ActionSetError` Lua event when result != 1). The 4 dwords are zeroed in the player ctor `1403e1400`. Raw byte scan of `0x1448` found no other writer of this class.
- Packet layout (matches `NexusForever.Network.World...ServerActionSet`): 3-bit SpecIndex, 2-bit Unlocked, 6-bit Result, 6-bit count, then actions.
- Meaning: `SpecChanged_Raise` `1403cd800` sends `ClientSetSpec` (0x174) only if the flag is set, otherwise raises Lua `SpecChanged(spec+1, 5)` (IndexLocked). Lua `AbilityBook.GetNumUnlockedSpecs` counts the set flags (loop at `140748eb7`); `SetCurrentSpec`/`NextSpec`/`PrevSpec` (`140748c40/d40/dd0`) test them. So Value N = "action set N (0-based) is unlocked".
- Server: already sends 0x019D with `Unlocked = 1` whenever it publishes a set (`SpellManager.ActionSetPublication.cs:220`, `ActionSet.cs:391`); there is no per-set locked state and no handler for `SpellEffectType.UnlockActionBar` (0x14, enum only). A faithful check needs a per-spec Unlocked bool on the player, sent as `Unlocked`.

## Q2. Type 226 Entitlement: character plus account entitlement amount. Confidence: read directly for evaluator and lists; the "count truthiness" step is inferred.
- `1404a1620(this, subject, comparison, ObjectId)`: subject type 0x14/0x17 else 0. `n = 1403d2140(player, ObjectId)`. Equal (1) returns n (non-zero is true); NotEqual (2) returns n == 0; all other comparisons 0. **Value is ignored** (dispatcher passes only subject, comparison, ObjectId). The dispatcher result is tested for zero by callers (inferred).
- `1403d2140` = entitlement amount: sum of character list `player+0x7f58` (count `+0x7f60`, 16-byte entries: `+8` entitlement id, `+0xc` amount) and account list `accountItemList(DAT_140c635f0+0x15d0)+0x98` (count `+0xa0`), capped by `Entitlement` row `+4` (MaxCount; 0 or no row means 0xffffffff). Same function as type 273 (EntitlementCount). Not account items.
- Fillers: character list by `FUN_1403d1e40` (raises Lua `CharacterEntitlementUpdate`), called from PlayerCreate apply `1403b5f80` and from opcode **0x0918 ServerEntitlement** (call `1403f1023`, case `1403f1017`). Account list by `LuaEvent_AccountEntitlementUpdate_Raise_1400062c0`, from `AccountInventory_HandleServer0966To0980` `140003fb0` (0x0968 ServerAccountEntitlements, 0x0973 ServerAccountEntitlement by repo opcode names; the opcode-to-branch mapping of this handler was not individually checked).
- Server names: `player.EntitlementManager.GetEntitlement(type).Amount` plus `player.Account.EntitlementManager...Amount`, capped by `gameTableManager.Entitlement.MaxCount` (exactly as `PrerequisiteCheckEntitlementCount`). Type 226 = "total > 0" for Equal, "total == 0" for NotEqual.

## Q3. Type 244 OwnsAccountItem: wrong name, it is **HasBindPoint**. Confidence: read directly.
- `14049ca70(this, subject, comparison)`: subject 0x14/0x17 else false; `lookup = 1401ed460(player+0x1694)`; `1401ed460` is the **BindPoint.tbl** row lookup by id (`PTR_u_BindPoint_140a69480`). Equal = row exists, NotEqual = no row. **ObjectId and Value are ignored.** Identical to Lua `HasBindPoint` `Lua_T140b72d30_HasBindPoint` `1406fbe80` and `FUN_1404de660`.
- `player+0x1694` = current bind point id. Writers: PlayerCreate apply (`1403b6200` in `1403b5f80`) and `FUN_1403cbb10` (stores id, sets `+0x6f98 = 1`, fires UI event 0x4a), applied by opcode **0x016D** (call `1403ef399`, case `1403ef396`; reader registered in `14006c290`). Repo calls 0x016D `ServerActionSetUInt16`; `Player.Travel.cs:48` already sends it with `bindPointId`. So the server data is the player's bind point id (zero means none). Row 30314 uses it as "has any bind point".

## Q4. Type 18 ScheduledEvent: set filled by opcode **0x036F**. Confidence: writer read directly; meaning of ids inferred.
- `14049ef00(this, comparison, Value)`: no subject gate. Looks `Value` up in an `unordered_set<uint32>` at `DAT_140c65898+0x7290` (sub-object: bucket vector begin/end `+0x10/+0x18` = global `+0x72a0/+0x72a8`, element count `+0x28`; node = next pointer, key uint32 at +8, value dword at +0xc). Equal = present, NotEqual = absent.
- Only writer in the whole image (byte scan for `0x7290/0x72a0/0x72a8`): opcode **0x036F**, case start `1403ec896`, 8-byte payload read by `ServerUInt32AndFlag_ReadPayload` `14007c340` (32-bit id + 1 bit flag). Flag 0: insert id (`14043f330`, node value set to 1); flag 1: erase id (`14043f470`). Afterwards it calls `FUN_1405f9e30(DAT_140c65ba8+0xe0, id)`, the same dependency re-evaluation used by quest state and public events (ClientEventAction rows of types 1..3 and 7). Ctor `1403e2140` and dtor `1403e5099` only init and free it.
- Server: no opcode 0x036F in `GameMessageOpcode.cs`, no ScheduledEvent table or manager (only the enum name in `PrerequisiteType.cs`). Candidate id space (inferred, not proven): the id passed to the ClientEventAction dependency tracker; `LiveEvent.tbl` is a plausible source but no Lua or table link was found. Until the server emits 0x036F the set is always empty: Equal never true, NotEqual always true.
