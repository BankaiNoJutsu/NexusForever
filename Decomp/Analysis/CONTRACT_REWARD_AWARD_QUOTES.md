## Selected-cycle provenance

`ContractRewardClaimQuote.Capture` validates the complete copied Contract snapshot,
then requires the requested Character, active initialized track, cycle, revision,
earned point threshold, selected row and exact choice. It cannot initialize a
missing cycle, substitute an unselected row or fall back to another reward owner.
Independent active PvP/PvE types remain valid together.

Canonical version1 quote JSON retains Character/cycle/revision/points, the original
selection JSON and the entire award. Restore validates the complete award against
the frozen catalog and its original selected-cycle provenance. Unknown fields,
noncanonical JSON, removed credits, altered amounts/binding/quantities and changes
of reward/choice/cycle are rejected. Both completion-origin and choose-origin
selection formats remain supported without introducing a claim or acceptance ID.

The quote is a value description, not a signature, database witness or receipt.
Positive owner/revision values in a restored quote still need comparison with the
actual authorized owner and current SQL baseline. The later connected claim owner
must prove the snapshot was sent, acquire the existing actor/inventory save leases,
check the durable unclaimed slot, enroll the exact inventory and Character currency
effects, and retain a stable operation identity. Auth compensation additionally
needs durable idempotent handoff and recovery across either database commit. No
quote-only or inventory-only path may acknowledge a Contract claim.
