# The Gauntlet (world 2183, public event 446): restoration assessment (2026-11-09)

Asked by the user: "can we restore The Gauntlet?". Evidence: Mapped (client `PublicEventObjective` table, read by the lead with `scripts/instance_public_event_objectives.py`), Observed (video, from the expeditions packet) and Source (repo). No retail parity claim; nothing run in a client.

## What the repo already has
`Source/NexusForever.Script.Instance/Expedition/Gauntlet` (737 lines): `GauntletEventScript` drives the whole objective chain (Pilot Taboro, airlock, what-happened cinematic, switches and golden skulls, swarm pit, first arena, chamber of choices, the Splorg phase, the two branch arenas, main event, Goon Squad, Slice and Dice, Shock King, Brick Braggor, the final NPC talk, then `Finish`), boss kill-credit scripts, talk and product-endorsement scripts, and `GauntletEventScriptTests` covering the phases and transitions. The airlock and swarm-pit trigger positions are marked work-in-progress guesses in the code.

## What the client table says (the packet listed these as missing input)
Rows of public event 446 (lead-read): Activate Switches 1837 count 3; Golden Skulls 1957 count 10; Survive the Splorg 1967 type TimedWin, count 1, **failure time 132,000 ms (2 min 12 s)**; Collect Gauntlet Score Tokens 1974 type VirtualCollect count 100 and a second row 4670 type Script **count 20** with the same text; "Current Scoring" 1942 count 100; **"Complete Expedition: The Gauntlet within the time remaining" 4707, type ScriptWithoutMax, failure time 1,200,000 ms (20 minutes)**; Survive the First Arena 1854 count 3; Survive the Main Event 1875 count 3; Save Contestants from the Darkspur 1951 count 3; "Clear the second and third Arenas" 1896 count 2; Bash Brothers 1822 count 2; Voodoo Kin 1866 count 2; Brick Braggor 4671 count 1.
These agree with the video (10 skulls, 3 switches, 20 tokens, a timer that runs during cinematics) and replace the packet's "total timer not stated" and "swarm-pit timer unknown": the swarm-pit (Splorg) timer is 132 s and the expedition timer is 20 minutes.

## What the script and engine do with it
* The engine already enforces an objective's `FailureTimeMs` (`PublicEventObjective` creates a failure `UpdateTimer` from the table), so the 132 s Splorg limit applies once objective 1967 is active, which the script does.
* The script activates `CollectGauntletScoreTokens` 1974 (the virtual count-100 gauge) but **not objective 4670** (the count-20 script objective the video's "20 tokens" matches), **not 4707** (the 20-minute expedition timer, which no other instance script uses either) and **not 1942** (scoring). Whether retail showed 4670 and 4707 as separate tracker lines, and how tokens credit them, is not established by anything the lead has, so the script was not changed.
* Rows 1822, 1834, 1896 and 1951 (Bash Brothers, Handler and pets, second and third arenas, Darkspur) are partly wired (1951 and the Handler pair are activated in the chamber phase and main event); 1822 and 1896 are not used by the script.

## What cannot be restored from the available evidence
The arena bosses' ability lists (Shock King, Brick Braggor, Slice and Dice, Pyro and Maniac, Showtime, Championator and the others) have no named abilities in the 15 retail clips (second check pass); their Spell4 rows are `[DEPRECATE]` or untagged and the objective numbers match no tag family; the random arena pool order and per-run encounters are unknown. A provisional boss script would have to bind rows by name only, which the rules forbid.

## Clip evidence read afterwards (2026-11-09, lead read, Observed)
* **Tokens and the Splorg timer, agreed by three commentators and the table:** Maximus Engineer playthrough 2017-07-09 https://www.youtube.com/watch?v=AvLLXHAruGQ at 178 to 191 s ("grab these tokens and survive 2 minutes"); Maximus Warrior playthrough https://www.youtube.com/watch?v=Hkosub57mUM at 209 to 222 s ("a minute 20 seconds out of the two minutes to grab ... all 20 of them"); Stalker playthrough 2017-07-07 https://www.youtube.com/watch?v=nCJ0_qRseHA at 318 to 326 s ("I got 20 tokens"). The table's objective 4670 (count 20) and the 132 s timer on 1967 match; so the player-facing goal is 20 tokens inside the Survive the Splorg timer.
* **Bots and combat:** the Splorg only put you in combat when one hits your bot (Engineer, 233 s); not a mechanic the server models today.
* **Medal and timer:** a gold run took "a little bit over 10 minutes" (Warrior, 652 s); the veteran "uncut" run says "the timer is actually ticking down already" and "ticks down during" the cutscene (iBluair, https://www.youtube.com/watch?v=aJMOX5gtiOM at 20 to 66 s); golden skulls "are required to get the gold medal" (iBluair, 107 s); surviving the Splorg and collecting the bears is needed for gold (Maximus veteran walkthrough at 557 s). * **Arena encounters:** none of the unread clips (three 2017 class playthroughs, the 2014 Esper run) names an arena boss ability; the Esper run only discusses skulls.
Decision: slice 1 (activate 4670, then 4707) is now supported on the player-facing side, but the credit path for the tokens (how 4670 or 1974 is credited when a token is touched) is not in the repo or the evidence, so no code was written; adding the activation without a crediting source would leave the objective unfinishable. Open input: the token pickup mechanism (entity, spell or item) for virtual-collect objective 1974 and the script objective 4670.

## How virtual-collect and token objectives are credited, and a new table finding (2026-11-09)
* **Engine pattern:** `VirtualCollect` objectives (type 22) are credited either by loot (`LootInstanceItem` calls `PublicEventManager.UpdateObjective(VirtualCollect, itemId, progress)`) or by a script entity that calls `UpdateObjective(PublicEventObjectiveType.VirtualCollect, virtualItemId, 1)` on activation (Fragment Zero's `CargoCrateEntityScript` for virtual item 1176, Outpost M-13's `DeadM13MinerEntityScript`). The Gauntlet's gauge objective 1974 (VirtualCollect, count 100) has ObjectId 0 in the table, so no virtual item id is named for it, and the repo has no token entity script.
* **New finding (lead-read with `scripts/instance_target_group.py`):** objectives 1967 (Survive the Splorg, TimedWin, 132 s), 4670 (Collect Gauntlet Score Tokens, count 20, Script) and 1942 (Current Scoring, count 100) all carry ObjectId 6867, and `TargetGroup` 6867 contains Creature2 48554 and 69305, the Shock King (normal and veteran). `TargetGroup` 6831 (objective 1837) is the three electric-room door locks, which matches the repo's existing script. So the token, score and Splorg objectives are keyed to the Shock King creatures in the table, not to a separate token entity; how a token pickup relates to that group is not established. Do not infer that the Shock King casts or hosts the token room: only the shared key is known.
* **Consequence:** the crediting path for objective 4670 would have to be a script on the creatures of group 6867 or on token entities not yet identified; neither the repo nor the video says which. Wiring 4670 would be a guess, so the slice stays unwritten. The 20-minute objective 4707 has no ObjectId and no crediting need (it is a timer row), but its tracker semantics are the same open question.
Open input, narrowed: the entity that credits objectives 4670 and 1942 (a script on Creature2 48554/69305, or token entities); evidence would be a clip of the token room that names what gives the tokens, or a Creature2 row for a token entity (not searched by the lead yet: a Creature2 name search for "token" or "score" in the Gauntlet's world would be the cheap next step).
