# Prerequisite types 24, 25, 219 (and 149, 9, 146): native client read (2026-11-08)

Evidence tier: **native decompile/disassembly of WildStar64.exe (build 16042), Ghidra 12.1.4 headless, plus `Prerequisite.tbl`/`Datacube.tbl`/`DatacubeVolume.tbl`/`WorldLocation2.tbl`/`Spell4Effects.tbl` census**. Documentation only: no server code, tests or existing docs changed. "Server should" items are proposals; "inferred" marks anything not read from the client.
Technique: evaluator vtable slot -> state it reads -> the opcode handler that writes it. Evaluator context layout (decomp `FUN_1404a2100`): `param_3[0]` type, `[1]` comparison, `[2]` ObjectId, `[3]` Value.

## A. Types 24 and 25
**Evaluator**: both vtable slots (`+0x290`, `+0x298`) are `FUN_14049e640` (jump-table cases `0x18`/`0x19` pass `unit, comparison, param_3[3]` = **Value**). Disassembly: `BT [DAT_140c65898+0x6750], Value` (register bit index, so mod 32); comparison 1 returns the bit, 2 its negation, anything else 0. `DAT_140c65898` is the local player object. The client never looks at the entity or the target, so the server's "caster and target share a phase" (25) and "entity phase equals Value" (24) are both not this test.
**Writer of `+0x6750` (found)**: raw byte search (disp32 `50 67 00 00`/`4c 67 00 00`) hit undisassembled code at `1403ef12b..1403ef145`: the world-message dispatcher `FUN_1403ec6a0` (this = player, R8D = opcode, R9 = payload; jump table int32 at `1403f1344 + (opcode-0x61)*4`, entry for `0x171` at `1403f1784` -> `1403ef129`). The case does `player+0x674c = dword0; player+0x6750 = dword1`, then `FUN_1405f9e30(mgr+0x160, 0)` (map-region/world-location refresh) and `FUN_1405fbb10`. Registration `14006c290`: opcode `0x171`, size 8, reader `ServerTwoUInt32_ReadPayload` (`14007a040`).
**Packet mapping**: server `ServerPhaseVisibilityWorldLocation` (0x0171): `PhasesThatPerceiveMe` -> `+0x674c`, `PhasesIPerceive` -> `+0x6750`. Types 24/25 read only `+0x6750`. `+0x674c` is used only for "can the world object see me" (Lua `bCanSeeMe` `FUN_140744860`, readers `1403f7e50/1403f8070/1403f8270/140459330/14061b900/140623d40/14068a500/14068f700`). Adjacent case `0x172` (`ServerPlaneVisibilitySpellSlingerVoid`) writes `+0x6754/+0x6758`; `+0x6758` is tested as a mask by `FUN_14049e610` (type 232 Plane, not in scope). The constructor zero-inits all of them (`1403e2c86/8c`), so before packet `0x171` arrives every 24/25 Equal is false.
**Server today**: `Player.cs:1682` sends `PhasesIPerceive=1, PhasesThatPerceiveMe=1` once after add-to-map; there is no per-player mask. `PrerequisiteCheckInPhase`/`CanSeePhase` use `IWorldEntity.PublicEventPhase`, which comes from `EntityEvent.Phase` (public-event spawn phase), a different concept. With the default mask 1 and `PublicEventPhase` 0 both give the same answers as native (Equal true only for Value 0). They diverge for an entity inside a public event phase n > 0 (server says InPhase(n) true, native false) and for every 25 with a target.
**Data**: 24: Equal 85 / NotEqual 12 slots, Values 0..6, 8, 10, 11, 20; 25: Equal 43 / NotEqual 5, Values 0..10, 20; ObjectId is 0 except a few ignored ids (3013, 9179, 2664 ...). 134 prerequisite ids are referenced by `MapZoneHex`, `MapZoneHexGroupEntry`, `Spell4.Prerequisite`, `Item2`, `WorldLocation2`, `Creature2`, `Spline2(Node)`, `GossipEntry`, `VisualEffect`: this is the global world-phase gate (e.g. 539 = bit 0 Equal, 557 = NotEqual bit 1). `WorldLocation2.Phases` values are masks (1 for 4847 of 33396 rows; 4, 16, 253 ... present), consistent with bit indices 0..7.
**Producer of mask changes (inferred, not client-visible)**: spell effect `ChangePhase` (type 0x22, 161 `Spell4Effects` rows, no server handler, no client handler: the client only receives `0x171`). Its `DataBits00/01` hold small masks (1, 2, 4, 8, 16, 32, 64) like the packet fields; `DataBits02/03` look like clear masks (`0xFFFFFFEF`, `0xFFFFFFFD` ...); 40 rows have a duration. Which data word maps to which packet dword and how clear masks combine is **not** determinable from the client.
**Server should**: add `IPlayer.PhasesIPerceive`/`PhasesThatPerceiveMe` (default 1/1) used by the packet at `Player.cs:1682` and re-sent when they change; replace both checks with `flag = ((player.PhasesIPerceive >> (int)(value & 31)) & 1) != 0`, Equal -> flag, NotEqual -> !flag, others false; subject = the evaluating player (non-player subjects: no native meaning, inferred default mask 1). Keep entity `PublicEventPhase` out of it. Tests (first): default mask Value 0 Equal true / Value 1 false / NotEqual inverse; mask 0b100 Value 2 true; Value 33 wraps to bit 1; packet before send (mask 0) Equal false; target and `PublicEventPhase` ignored; the existing `PrerequisiteCheckTests` 24/25 cases (lines ~2058-2090) encode the old semantics and must be rewritten.
**Unknowns**: what retail gameplay sets bits other than 0 (ChangePhase mapping above, quest/public-event scripts); whether another writer reaches `+0x6750` through a sub-object base (raw search of all `.text` found only the ctor and this case).

## B. Type 219
**Evaluator**: slot `+0x668` = `FUN_1404a15d0(this, unit, comparison, ObjectId)` -> `FUN_1404a80b0(DAT_140c659b0, ObjectId)`. Unit must be Player (0x14) or Ghost (0x17), otherwise 0 for every comparison (NotEqual too). Comparison 1 returns the flag, 2 its negation, else 0. 3 retail slots, all NotEqual, Value 0: prerequisite 22523 (volume 1), 35329 (volume 373), 35330 (volume 371).
**Flag** (`1404a80b0`, disassembly confirms args pass straight to `1404a8430`): look up the volume id in the std::map head at `mgr+0x438` (record `+0x20` id, `+0x24` collected-bit word); absent -> 0. `need = FUN_1404a8430(mgr, id)`; `need == 0` -> 0; else `popcount32(word) >= need` (octal-trick popcount, `SETNC`).
**Required count** (`1404a8430`): player faction = `DAT_140c65898+0x1bf0` object's virtual `+0x18`; 0xa6 selects the map at `mgr+0x68`, 0xa7 the map at `mgr+0x88` (other factions -> need 0); value node `+0x28` -> vector of datacube pointers; `need = vector size`. **Built at load by `FUN_1404a8d30`** from `Datacube.tbl`/`DatacubeVolume.tbl`: a datacube is kept only if its `WorldZoneId` row exists; for each `DatacubeId00..15` (nonzero, existing, kept) the first one fixes the volume faction and later ones with a different `DatacubeFactionEnum` are dropped; a volume with no kept datacube is discarded; a volume is added to the 0xa6 map when faction in {0,2} and to the 0xa7 map when in {0,1}. So `DatacubeFactionEnum` 0 = both, 1 = only 0xa7, 2 = only 0xa6 (with NF `Faction` Dominion=166/Exile=167: 1 = Exile, 2 = Dominion). `ZoneCompletionProgressTracker.DatacubeMatchesPlayerFaction` maps 0=Exile, 1=Dominion, else both, which disagrees with this loader (separate item, not verified against its use).
**Packets that fill `+0x438` records**: `ServerDatacubeUpdateList` (0x00E0, apply `FUN_1404a75d0`: clears the three maps, then volume array -> `+0x430` map, key = id, `+0x24` = Progress verbatim), `ServerDatacubeVolumeUpdate` (0x00E2, apply `FUN_1404a7d40`: erase + insert the pair). The server already sends both with `Datacube{DatacubeId, Progress}` for `Journal` (and `Chronicle`, which lands in the same client map under its Datacube id; an id collision with a volume id is not excluded). `SimpleEntity.OnActivateCast` sets `Progress |= 1 << QuestChecklistIdx` for `CreatureEntry.DatacubeVolumeId`, so popcount equals collected creatures.
**Retail rows**: volume 1 = datacubes 53,54,55 all with `WorldZoneId` 0 -> no kept datacube -> never registered -> flag always false (NotEqual always true); volume 373 = datacube 770 (faction 1, zone 4375): need 1 for 0xa7, 0 (unregistered) for 0xa6; volume 371 = datacube 771 (faction 2): need 1 for 0xa6 only. Of 401 volumes: 388 have one kept datacube, 7 lose entries, 8 are discarded.
**Server should**: replace `PrerequisiteCheckVolume`'s `DatacubePrerequisiteHelper.MeetsProgress` use with: subject must be a player; `need` = count of nonzero `DatacubeVolume.DatacubeIdNN` whose `Datacube` row exists, whose `WorldZoneId` row exists and whose `DatacubeFactionEnum` equals the first kept entry's, 0 if the volume's faction is not in the player's allowed set (see mapping above); `flag = need > 0 && journal != null && BitOperations.PopCount(journal.Progress) >= need`; Equal -> flag, NotEqual -> !flag, others false; Value ignored. Cache `need` per (volume, faction). Tests (first): three-datacube volume with 2 then 3 bits; volume 1 never complete; faction-1 volume for the other faction (NotEqual true even when collected); mixed-faction volume drops later entries; missing record; non-player subject; Value non-zero ignored. Type 218 (`Datacube`) stays as is (audit).
**Unknowns**: which of 166/167 the client's faction object returns for Exile (taken from NF's enum); whether Chronicle ids shadow volume ids in practice.

## C. Types 149, 9, 146
**149**: `FUN_14049c840(this, unit, comparison, Value)`: `state = (unit+0x1e4 != 0) \|\| (unit+0x2ac != 0)`, Equal `state == Value`, NotEqual `!=`. `+0x2ac` is the same field type 28 (InCombat) reads. `+0x1e4` is only written by the unit constructor (`140454380`) in the unit class; its writer/meaning unresolved (also `1405212e0`, other class). Slots: 30 Equal 0, 13 Equal 1, 2 NotEqual 1, 1 NotEqual 0; used by `Spline2Node` (994 nodes), `Creature2`, `Spell4Effects`, `Spell4Visual`: a unit-busy gate. Needs the `+0x1e4` writer before a check; "InCombat only" would be a guess.
**9**: `FUN_14049f700(this, unit, comparison, ObjectId, Value)`: episode object from the hash map `DAT_140c665d8` (id key; built by `FUN_140723ce0` from `Episode.tbl` + `EpisodeQuest.tbl`), `state = vtable+0xc0` = `FUN_140788b50`: over the quest-state map at `episode+0x50` (nodes `+0x20` quest id, `+0x24` state): all nodes == 3 (or map empty) -> 3, else the maximum non-3 state; `flag = (state == Value)`; Equal returns it, NotEqual negation. Lua `EpisodeState_Unknown 0, Mentioned 1, Active 2, Complete 3`; 33 of 34 slots use Value 3. Likely meaning (inferred): every `EpisodeQuest` row of the episode has the player's quest in `QuestState.Completed (3)`; node values appear to mirror quest states (numeric enum equal on the server). Not verified: the writer of the `+0x24` nodes and whether the map holds every episode quest. Server has `EpisodeQuest` rows and `QuestManager`; the check is feasible once the node writer is confirmed.
**146**: evaluator passes `param_2[2]` (not the unit slot `[0]`) as the object; `ObjectId` is a **`TradeskillTier` id** (`FUN_140246480` looks up `TradeskillTier`), not a tradeskill id 1..16 as noted before; tier-threshold list (stride 0x30, `+0x34`) from `DAT_140c65b90`; the index reached is compared with Value (0, 1, 10). Which object `param_2[2]` is and the source of its words `+0x15c/+0x160` remain open.

## Tooling notes
New helper `I:\tools\scripts\FuncOf.java` (function containing an address). `DecompForce` created function entries in the Ghidra project at several addresses, including a bogus one at `1403ef0f0` (inside undisassembled switch code; ignore it). The `1403ec6a0` dispatcher and its `1403ef...` cases are not functions in the project; use `Disasm.java` from the case address. Python parsers for the `.tbl` files were kept in the session scratchpad only.

Lead review and implementation (2026-11-08): the native claims are the agent's reading and were not re-derived by the lead (the dispatcher case found by raw byte search, the loader rules, the faction mapping). **219 is implemented** as `PrerequisiteCheckVolume(IGameTableManager)`: player subjects only, need = number of kept datacubes (WorldZone row exists, first kept datacube fixes the volume faction, later ones of another faction dropped) allowed for the player's faction (0 both, 1 Exile, 2 Dominion), `flag = need > 0 && popcount(Journal progress) >= need`, Value ignored; tests `VolumeCompletionPrerequisiteTests` (13 cases) written before the class; the superseded `Volume_UsesJournalDatacubeType` test now supplies the volume tables. Prerequisite+Datacube+Volume filter: 1,727 cases pass (Source/SQLite scope). Journal-only progress is inferred (the client keeps chronicles in the same map). **24/25 are not implemented yet**: replacing the entity `PublicEventPhase` test by the player's `PhasesIPerceive` bit is native-correct but the server has no producer for mask changes (the `ChangePhase` spell effect has no handler) and public-event content may depend on the current entity-phase gating, so the change needs a design decision on how public event phases reach the player mask. 149, 9 and 146 stay open (149 needs the writer of unit `+0x1e4`; 9 needs the writer of the episode quest-state nodes).

Implementation (2026-11-08, later): **24 and 25 are implemented** as the native test. `IPlayer.PhasesIPerceive` / `PhasesThatPerceiveMe` (default 1/1, `Player.cs`) hold the two dwords of packet 0x0171; `IPlayer.SetPhaseVisibility(iPerceive, perceiveMe)` replaces both and re-sends the packet when either changed; the login send uses the same members. `PrerequisiteCheckInPhase` and `PrerequisiteCheckCanSeePhase` both evaluate `((PhasesIPerceive >> (Value & 31)) & 1) != 0` through `CompareFlag` (Equal flag, NotEqual its negation, others false) and ignore the entity, the target and ObjectId; a non-player subject uses the default mask 1 (inferred, no native meaning). Tests `PhaseMaskPrerequisiteTests` (14 cases) were run red first (10 of 14 failed against the old checks, 4 passed by coincidence), then green. Two old tests encoding the superseded reading were replaced rather than weakened: `InPhase_ComparesPublicEventPhase` / `CanSeePhase_ComparesPlayerAndTargetPhase` in `PrerequisiteCheckTests` (now covered by the new file) and the type 24 row of `UnitPrerequisiteContextTests.ExistingUnitStateProxiesKeepTheirScalarBehaviorOnTheExplicitSubject`. Filter Prerequisite|Phase|PublicEvent|Player: 4,352 cases pass (Source/SQLite scope).

Correction to the earlier plan: `WorldEntity.PublicEventPhase` is `EntityEvent.Phase` spawn data, not a live public-event phase, so there is nothing in the server to "feed" into the mask and no producer was invented. **Behavioural consequence**: while no code ever changes the mask (the `ChangePhase` spell effect still has no handler) every 24/25 with a Value other than 0 is now false for players, where the old check returned true for an entity whose spawn phase equalled Value. That matches the client's own test; whether content that depended on the old coincidence exists is not verified. Open: mapping of `ChangePhase` data words to the two packet dwords (not determinable from the client).
